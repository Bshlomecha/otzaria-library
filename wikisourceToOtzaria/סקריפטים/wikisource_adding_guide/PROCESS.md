# התהליך: הוספת ספר אחד מוויקיטקסט לספרייה (צעד אחר צעד)

כל הנתיבים יחסיים לשורש הריפו. לקיצור: `G=wikisourceToOtzaria/סקריפטים/wikisource_adding_guide` (תיקיית הערכה), `WORK=~/ws_work/<id>` (תיקיית עבודה **מחוץ**
לריפו - אל תכתוב קבצי עבודה לריפו). בפקודות: `python` = Python 3.12+ מה-venv (ראה [TOOLS.md](TOOLS.md)), תמיד עם `-X utf8`. בחלונות הקונסולה משבשת עברית -
כתוב פלט לקבצים וקרא אותם (כלי הקריאה/עורך), ואל תסיק מסקנות מתצוגת קונסולה.

אחד-אחד: סיים ספר (קומיט) לפני שמתחילים את הבא. ספר = בסיס + (אם יש) "הערות על ..." + קובץ links.

## 0. הכנה (פעם אחת)

```bash
git status --short            # מה כבר לא-מעקוב/מבוים אצלך (אינו שלך - אל תיגע)
git log --oneline -5
python -X utf8 $G/scripts/ws_book.py --help        # הכלי נטען? (לא טוען את המנוע; ראה TOOLS.md לבדיקת תקינות מלאה)
```
קרא קודם את [ADDING_BOOKS.md](../../../ADDING_BOOKS.md) ו-[CLAUDE.md](../../../CLAUDE.md) בשורש הריפו, ואת הסקיל `.claude/skills/otzaria-book-format/SKILL.md`
(חוזה ה-markup: כל שורה בקובץ היא יחידה; `<h1>` בשורה 1; שורה 2 מחבר; הערות כספר נפרד + links). כל הקובצים כאן נכתבים בקידוד UTF-8, **LF**, בלי BOM.

## 1. בדיקת קיום (חובה, לפני שמורידים כלום)

הכלל: ספר ש"נראה חסר" לפי שם - לעתים קיים בשם אחר, בתוך ספר אחר, או חלקי במקור אחר. הסוכן הראשון כאן טעה פעמיים: **"ספר תגין"** נראה לו חלקי כי בדק
רק חלק מהערך (הוא כולו בתוך "אוצר מדרשים", שורות 6091-7966); ו**"טור ברקת"** לא נמצא לפי שם כי השם בקובץ הוא "מקור חיים - ג (טור ברקת חלק א/ב/ג)".

**א. בריפו** (שמות קבצים + מרשמים; מסמן `[נארז]` מול `[לא-נארז]` - רק נארז נחשב "קיים בספרייה"):
```bash
python -X utf8 $G/scripts/check_exists.py "שם הספר" "שם חלופי" "שם המחבר"
```
עותקים מקבילים באותו שם קיימים כמעט תמיד (`extraBooks/`, `לא רלוונטי/`, `בהמתנה/` ... - לא נארזים). ספרי **ספריא אינם בריפו כלל** (נוצרים בבנייה מה-API) - רק ב-DB.

**ב. ב-`seforim.db` החי** (קריאה בלבד). מציאת הקובץ: `python -X utf8 $G/scripts/db_search.py find` (במחשב אחר הנתיב שונה; בחלונות בד"כ
`C:\ProgramData\otzaria\books\seforim.db`; אם לא נמצא - בקש מהמשתמש). התוכן ב-`line_content` דחוס zstd עם מילון מהטבלה `zstd_dict` - הכלי מטפל בזה.
```bash
python -X utf8 $G/scripts/db_search.py --db <DB> title "תולדות תנאים" "סדר תנאים"          # לפי שם (מנורמל: בלי גרשיים/ניקוד/מקפים)
python -X utf8 $G/scripts/db_search.py --db <DB> tree "ספרות עזר"                          # עץ הקטגוריות (לבחירת קטגוריה קיימת)
python -X utf8 $G/scripts/db_search.py --db <DB> text "ביטוי ייחודי 1" "ביטוי ייחודי 2" --max-hits 3    # טקסט מלא (6-7 דקות)
```
**חיפוש הטקסט המלא הוא החלק החשוב**: קח 2-3 ביטויים *ייחודיים* מתוך גוף הספר בוויקיטקסט (תחילה/אמצע/סוף - לא מהכותרת), וחפש אותם בכל ה-DB. ביטוי
שמופיע ברצף בספר אחר ארוך = הספר כלול שם. חפש גם בשם המחבר ובשם הספר בגרסאות איות שונות. שים לב: ה-DB משקף את הבנייה האחרונה.

**החלטה:** (1) קיים במלואו - אל תוסיף, דווח (כך נקבע ל: מעשה רוקח, ספר תגין, אלדד הדני). (2) קיים חלקית/ממקור אחר (רוקח על שיר השירים בדיקטה; טור ברקת בדיקטה) -
הוסף רק אם נאמר במפורש; החלפת קובץ של מקור אחר - רק באישור המשתמש (ראה BLOCKED_BOOKS). (3) לא קיים - המשך.

## 2. `--plan-only` קודם (בלי המרה)

```bash
python -X utf8 $G/scripts/ws_book.py --page "<כותרת הדף הראשי כפי שבוויקיטקסט>" --out "$WORK/plan" --plan-only --delay 1
```
פתח `$WORK/plan/_report/<שם>.report.txt` ובדוק **ידנית מול הדף הראשי בוויקיטקסט** (בדפדפן, או `curl "https://he.wikisource.org/w/index.php?title=<כותרת מקודדת>&action=raw"`):
- **סדר הדפים** ("תוכנית הדפים") תואם לתוכן העניינים של הספר. הסדר נקבע לפי הקישורים בדף הראשי/בדפי הפרקים, לא לפי א"ב.
- **תתי-דפים שדולגו** (דף "הכול"/"שלם"/תוכן/ניווט - תקין) ו**תתי-דפים שלא מופיעים בתוכן העניינים** (נכללו בניחוש סדר - לבדוק ידנית).
- **דפים אדומים** (קישור בתוכן לדף שלא קיים) / **חסרים** / **ריקים**: הספר חלקי? ראה "קטגוריות הדף הראשי" בדוח: `ספרים מושלמים` / `טקסט מושלם` = שלם;
  `ויקיטקסט:טקסטים שלא נשלמו` / `דפים לא גמורים` או תבניות `{{בעבודה}}` = חלקי. (המשתמש מרשה חלקי - סמן בתיאור ובדוח.)
- **שלמות מול דף "הכול"/"שלם"** (אם קיים): בהרצה מלאה מופיע "השוואה לדף הכול" - יחס רחוק מ-1 = לבדוק.
- **"מילות טקסט בדף הראשי ... יש טקסט משמעותי"**: אולי צריך `--include-main` (אבל **לא** כשהדף הראשי כולל בעצמו את תתי-הדפים - תקבל כפילות).
- **אזהרה "אין תתי-דפים והדף הראשי נראה כתוכן עניינים"**: הספר בנוי מדפים שאינם תתי-דפים ("קהלת משה א ב") - דרוש driver (examples/kohelet_moshe_driver.py).
- דפי `<pages>` ("תג <pages> ... לא נתמך"): הטקסט יושב בעמודי סריקה - ראה examples/selichot_baer ו-examples/toldot_tanaim.
- **נחסם בנטפרי: ...** - ראה כלל 1 ב-README: עצור, דווח. אל תכתוב ספר מדפים שנכשלו.

## 3. הרצה מלאה

```bash
python -X utf8 $G/scripts/ws_book.py --page "<כותרת>" --out "$WORK/out" [--name "<שם הספר ב-h1>"] [--author "<מחבר>"] [--template-map tm.json] [--delay 1]
```
`--name`: ברירת המחדל = כותרת הדף בלי הסוגריים שבסופה (`ספר זכרון (ריק"ם)` -> `ספר זכרון`); חובה `--name` כדי להבדיל משם תפוס (`קהלת משה (משה הכהן)`).
**קוד יציאה 0 אינו אומר "נקי"** - הכלי מחזיר 0 גם עם ממצאים ("נכתב - יש ממצאים לבדיקה"). קרא את הדוח:

1. **תבניות לא ממופות** - כל תבנית כאן הוחלפה בפרמטר המיקומי האחרון שלה (לעתים נכון, לעתים מוחק טקסט). לכל אחת: פתח דף דוגמה, החלט, והוסף ל-`tm.json`.
   פעולות: `remove`, `keep_all`, `keep_first`, `keep_last`, `bold`, `big`, `small`, `italic`, `parenthesize`, `line_break`, `new_line`, `underline`, `literal:טקסט`.
   ```json
   {"גמט דגש": "keep_last", "טקסט מנוקד": "remove", "סוף": "remove", "עוגן בשורה": "remove"}
   ```
   (דוגמאות מהעבודה הקודמת: "גמט דגש" x266 בטור ברקת; "טקסט מנוקד"/"סוף" בראה מעשה; "עוגן בשורה" במכלול.) תבנית שדורשת לוגיקה - ראה examples/shlosha_dikduk/wrap.py.
2. **שאריות סימון** (`{{`, `}}`, `[[`, `]]`, `<ref`, `''`/`'''`, `__HTML_REGION_`, `{|`, `<pages`, `&lt;`, ...): כל אחת - לבדוק שורה. (`''` אחרי ה' בסוף ציטוט - `ימלטהו ה''` - מקרה ידוע בראה מעשה.)
3. **בדיקת שימור טקסט** (טוקנים עבריים מקור מול פלט) - **"חסרים" רבים אינם בהכרח אובדן**: קידומות+קישור (`ב[[...]]`), `{{נ|תיקון|ד"ו=...}}` (מציג רק את הנוסח המתוקן),
   שמות צבע (`ירוק` x4225 במכלול!), מספרי עמוד. כדי להכריע - `qa_vs_rendered.py` (משווה ל-HTML המרונדר) ו/או השוואת difflib לפי ADDING_BOOKS סעיף 0.
4. **חוזה המיזוג** (כשיש הערות): חייב "תקין". האזהרה "קובץ הערות שמתחיל בכותרת - הערה N יושבת בשורה N+1" צפויה.
5. **תוצאת הוולידטורים** בסוף הדוח (`validate_book`, `validate_sidecars`): 0 שגיאות.

קרא ידנית (כלי Read): תחילת הקובץ, אמצע, סוף, כל הכותרות (`python -X utf8 .claude/skills/otzaria-book-format/scripts/inspect_book.py "<קובץ>" --toc --stats`), ודוגמאות הערות.
טקסט המקור נשמר כמות שהוא: **אין לתקן לשון**, רק סימון שבור. אם התיקון הידני הכרחי ושורד המרה חוזרת - ראה `wikisourceToOtzaria/post_convert_fixes.tsv` (קבצי הדוגמה שם).

## 4. מלכודות שכיחות (פירוט ב-[LESSONS.md](LESSONS.md))

HTTP 429 (חכה והרץ עם `--delay 2`-`3`); הדף הראשי הוא רק תוכן עניינים ולא "/"; דפי `<pages>`; הערות בפורמט ftn/ftnref או `{{הערה}}`; `{{דף שער}}` נמחק (הדבקה ידנית);
רמות כותרת; `{{ק|` בשבירת סוגריים; `<h1>` בדפוס שונה משם הקובץ (מעשה אפד/אפוד); `mismatch` בדפי מרחב "עמוד:"; חוזה footnotes; שורת זכויות.

## 5. שורת זכויות יוצרים (שורה 3)

הכלי מוסיף אותה אוטומטית. **ודא שהיא מדויקת לתו** מול ספר קיים (`wikisourceToOtzaria/ספרים/אוצריא/ספרות עזר/דקדוק/ספר הרכבה.txt`, שורה 3; LF, בלי רווח/שורה בסוף):

```html
<p style="color: gray;"><small><small>באדיבות "וויקי-טקסט", נלקח מהדף: <a href="https://he.wikisource.org/wiki/{enc}">כאן</a>, בשימוש בהתאם לרישיון CC BY-SA 3.0. בוצעו שינויים בעיבוד, להתאמה לאוצריא.</small></small></p>
```
כאשר `{enc}` נוצר כך: `urllib.parse.quote(title.replace(' ', '_'), safe='')` - כש-`title` = כותרת **הדף הראשי** בוויקיטקסט (עם רווחים, כפי ש-`--page` קיבל). בספרים רב-דפיים - לדף הראשי, לא לפרק.
דוגמאות: `ספר זכרון (ריק"ם)` -> `%D7%A1%D7%A4%D7%A8_%D7%96%D7%9B%D7%A8%D7%95%D7%9F_%28%D7%A8%D7%99%D7%A7%22%D7%9D%29`; `כף החיים (פאלאג'י)` -> `...%28%D7%A4%D7%90%D7%9C%D7%90%D7%92%27%D7%99%29`.
(זה הפורמט שנקבע בקומיט `7f3769b29d6db52f463d4d0abfe9d9a6138668f7` - "זכויות יוצרים: וויקיטקסט".) בדיקה מהירה לכל הקבצים החדשים:
```bash
for f in <קבצי הספרים>; do sed -n 3p "$f" | grep -c 'CC BY-SA 3.0. בוצעו שינויים בעיבוד, להתאמה לאוצריא.</small></small></p>$'; done   # 1 לכל קובץ
```
**שימו לב:** הוספת/הסרת שורה בקובץ בסיס מזיזה את כל `line_index_1` בקובצי ה-links שלו (כך קרה בקומיט הזכויות - עדכנו את כל קבצי links). אם עורכים את הבסיס אחרי יצירת ה-links - צריך לחשב אותם מחדש.
בקובץ "הערות על ..." אין שורת זכויות (שורה 1 = h1; ההערות מתחילות משורה 2).

## 6. שם קובץ, שם ייחודי, קטגוריה, מחבר

- **שם הקובץ** = שם הספר אחרי ניקוי: בלי ניקוד ובלי `\ / : * " ״ ? < > |`; `_` -> רווח; `''` ו-`'` נמחקים. ה-`<h1>` שומר את הצורה המלאה (גרשיים וכו'); **הם לא חייבים להיות זהים**.
  (`הקדמת הרמב"ם למסכת מנחות` -> `הקדמת הרמבם למסכת מנחות.txt`.) הכלי עושה זאת (`sanitize_filename`) ומדפיס את שם הקובץ בדוח.
- **שם פנוי:** `python -X utf8 .claude/skills/otzaria-book-format/scripts/make_metadata.py --title "<שם הקובץ בלי .txt>" --check-name --repo .` ובנוסף
  `db_search.py title "<שם>"` (שם ב-DB הוא שם הקובץ אחרי נרמול גרשיים; התנגשות עם ספר ספריא/אחר באותו שם = בעיה). אם תפוס - שם מבדיל בסוגריים: `קהלת משה (משה הכהן)`.
- **קטגוריה** = תיקייה: `wikisourceToOtzaria/ספרים/אוצריא/<קטגוריה>/<קובץ>.txt`. הקטגוריה נגזרת מנתיב התיקייה, וכל שורשי הספרים ממוזגים לעץ אחד לפי נתיב -
  ולכן **השתמש בשם תיקייה קיים בדיוק כפי שהוא** (למשל `משנה/ראשונים/רמבם` - בלי גרשיים; `שות/אחרונים`). בחר לפי ספרים דומים (`db_search.py tree`, ו-`check_exists.py` על ספר דומה). אל תמציא
  קטגוריה אלא אם אין בררה (ואז הסבר). קטגוריות מוצעות לכל ספר - ב-BLOCKED_BOOKS (הצעות; לאמת מול העץ החי).
- **מחבר:** `author.name` הוא **מפתח ייחודי** - שתי כתיבות של אותו אדם = שני מחברים, ומאז חיפוש לפי מחבר חצי מספריו לא נמצאים. חפש את הצורות הקיימות ב-`metadata.json` ו-`ForDB/book_info.csv`
  (`check_exists.py "פלאג'י"`; למשל "אליהו בחור", "יוסף קמחי", "רבנו דוד ב"ר יוסף קמחי", "רב ניסים גאון", "חיים פלאג'י") **והשתמש בצורה הקיימת**. הערה: בספרייה קיימות לפעמים כמה צורות (כף החיים:
  `ר' חיים פאלאג'י (נלב"ע תרכ"ח)`; ספרים אחרים: `חיים פלאג'י`) - הכרע, ודווח. שם המחבר נכנס לשורה 2 בקובץ וגם ל-`metadata.json` (ה-`author` שם הוא שמזין את טבלת המחברים).
- **שנים/דור:** אל תמציא. השנים ב-`book_info.csv` של "ספר הבחור" (1038-1492) כנראה שגויות (טווח גס של "ראשונים"); "ספר הרכבה" נרשם 1469-1549 ללא אימות. ודא מול מקור שאפשר לצטט (דף המחבר בוויקיטקסט; ויקיפדיה - נחסמה
  בנטפרי בעבודה הקודמת, אצלך אולי פתוחה). מה שלא ידוע - ריק. דור: `ראשונים`/`אחרונים`/`חז"ל`/`מחברי זמננו`/`תורה שבכתב` (+ תת-דור אופציונלי) לפי נוהג הספרייה.

## 7. העתקה לריפו + רישום ב-3 המרשמים

העתק **רק**: קובץ הספר (`.txt`), אם יש הערות - `הערות על <שם>.txt` באותה תיקייה, וקובץ `<שם>_links.json` (צעד 8). אל תעתיק `_report/`.

```bash
cp "$WORK/out/<שם>.txt" "$WORK/out/הערות על <שם>.txt" "wikisourceToOtzaria/ספרים/אוצריא/<קטגוריה>/"
```
מרשמים - שלושה, בפורמטים מדויקים ([ADDING_BOOKS.md](../../../ADDING_BOOKS.md) סעיף 5; פורמט אחר משכתב את כל הקובץ): `metadata.json` (שורה דחוסה אחת לספר, בסוף המערך), `ForDB/book_info.csv`
(LF, `QUOTE_ALL`, ממוין, בלי BOM; דרך `.github/scripts/book_info_writer.py` - **דוחה CRLF**), `ForDB/sefaria_metadata_changes.csv` (תיאור; `title` = שם הקובץ בלי `.txt`).
`ForDB/all_metadata.json` - רק 6 ספרי wikiSource רשומים שם; לא חובה. **ספר ההערות אינו נרשם**, רק הבסיס. הכלי שעושה את כל זה בפורמט הנכון ועל עותקי LF:
```bash
# 1. כתוב $WORK/meta.json - מערך רשומות (שדות ב-register_metadata.py ובדוגמאות scripts/examples/meta_samples/)
```

## 8. קישורי הערות (`links`) ועדכון ה-lineage

**מתי:** רק כשיש "הערות על <שם>" (ספר נלווה). אחרת - דלג. (בחירה: ספר נלווה + links הוא הנוהג; הערות inline `<sup class="footnote-marker">`+`<i class="footnote">` נחשבות לגיטימיות רק כשאין
אפשרות אחרת - בעבר, כש-`wikisourceToOtzaria/links` היה absent, הסליחות הוכנסו כך.)

חוזה ה-footnotes (פורט ב-ADDING_BOOKS סעיפים 2-4; `ws_book.py` מאמת אותו ומדווח ב"חוזה מיזוג הערות"): בלי `ref_2`; מפתח `"Conection Type"` (n אחת) = `"footnotes"`; `path_2` = `"הערות על <שם>.txt"`;
`heRef_2` = `"הערות"`; אין `<sup class="footnote-marker">` בבסיס; בספר ההערות אין `<i>`, כל שורה לא ריקה ולא כותרת מקושרת; שם ספר ההערות מתחיל ב-`הערות על ` בדיוק; ספר ההערות מתחיל ב-`<h1>` ולכן הערה N בשורה N+1.

1. העתק `$WORK/out/links/<שם>_links.json` ל-`wikisourceToOtzaria/links/` (**שטוח**, בלי תתי-תיקיות; שם ייחודי; LF - הכלי כותב LF; אל תפתח/תשמור בעורך שממיר ל-CRLF).
2. `python -X utf8 .claude/skills/otzaria-book-format/scripts/validate_sidecars.py --links wikisourceToOtzaria/links/<שם>_links.json --book "<קובץ הבסיס>" --target "<קובץ ההערות>"`.
3. **lineage:** כל הוספה/שינוי של קובץ links (או של `manual_links_sync.json`) משנה את `manual_links_lineage.json` (שלושה שדות sha256: `config_sha256`,
   `source_links_tree_sha256`, `packaged_links_tree_sha256`), ואם הוא לא מעודכן - אריזת השחרור (`package`) נופלת. **חובה לחשב ב-LF** (במחשב המקורי `core.autocrlf=true`: `manual_links_packaging.py check`
   על עץ העבודה נותן hash שגוי כי הקבצים CRLF):
   ```bash
   python -X utf8 $G/scripts/recompute_lineage.py            # בדיקה: האם ה-lineage שבעץ העבודה נכון (קוד 1 + הערכים הנכונים אם לא)
   python -X utf8 $G/scripts/recompute_lineage.py --write    # כותב canonical_bytes(lineage)+LF ומאמת check --require-lineage
   ```
   הליך ידני שהסקריפט מממש (אם הוא לא רץ): חלץ `git archive HEAD` עם `-c core.autocrlf=false -c core.eol=lf` של `manual_links_sync.json`, `manual_links_lineage.json`, `manual_links_packaging.py`,
   `packaging_toolchain.json` ושורשי ה-links הנוכחיים, הוסף את קבצי ה-links החדשים (כ-LF), הרץ שם `python -I manual_links_packaging.py check` וקבל את שלושת ה-hashes, עדכן ב-lineage
   (`json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(',', ':'))` + `\n` - כלומר `canonical_bytes(lineage)+b'\n'`) ואמת `check --require-lineage`.
4. אם נדרש שורש links **חדש** (לא `wikisourceToOtzaria/links`): ראה את הקומיט `9a692fd2e` (הוספת `OraytaToOtzaria/links` ל-`manual_links_sync.json` + lineage). ל-wikisource השורש כבר `present`.
